# Air Map 開発計画

## 目指す体験

対象は「行きたい地域は決まっているが、使う空港を知らない国内旅行者」。日本には思っている以上に各地に空港がある。地図上の地点または囲んだ地域から、利用しやすい空港、そこへ就航する便、現地への移動を順に発見できるようにする。地域内にある空港だけでなく、地域外でも目的地へ行きやすい空港を候補に含める。

「日本国内で、行きたい地域から旅を組み立てる」
空港名を知らない人が「四国のこの辺へ週末に行きたい」と地図を囲み、使える空港・便・現地までの移動を一度に比べられる

航空券の「路線がある」「予定便がある」「概算価格がある」「現在の価格と空席を確認した」は異なる情報として扱う。データが欠けているときに「便なし」や「予約可能」と表示しない。

## 現在の基準点

- 地図、空港リスト、地域 GeoJSON、空港選択、Amadeus テスト環境による片道直行便検索がある。
- Flutter 3.40.0-0.1.pre で旧 `package:flutter_gen` 参照をプロジェクト内の生成コードに移行した。Android デバッグ版のビルドとエミュレータでの地図表示、iOS シミュレータ向けビルド、静的解析、画面テストを確認した。
- `build_runner` は現在の Dart SDK に対して `analyzer` の互換性警告を出すが、生成は成功する。依存関係の一括更新は別の作業として行う。
- `lib/airport_list.dart` には作業開始前から未コミットの変更がある。今後の作業でも保持する。
- 現在の Amadeus 検索は網羅的な国内便・運賃検索としては扱わない。テスト環境のデータは限定され、Self-Service には対象外の航空会社がある。

## 次に実装する順序

### 1. 路線・価格データの取得方法を決める（最優先）

先に四国を対象に代表的な出発地、地方空港、週末の日付を含む検証ケースを作る。候補ごとに、就航便の検出率、航空会社の網羅性、価格の一致、予約先へ進めるか、応答時間、契約条件、費用を記録する。

第一候補は Skyscanner 提携 API。探索画面には Indicative Prices の概算価格、利用者が空港と日付を決めた後には Live Prices と予約リンクを用いる。提携審査と予約への送客が前提であり、Live Prices の大量自動照会を設計に含めない。概算価格には「参考」「取得時点」を表示する。

路線・時刻表の補完候補は NAVITIME のフライト情報 API。時刻表データは別途契約が必要で、運賃・空席の情報源にはならない。Duffel と Amadeus 本番環境は、国内の必要な路線で実際の取得結果を比較してから採用を判断する。いずれかの契約が成立しなくても、就航情報と外部の予約検索導線で地域探索を提供する。価格を推測して埋めない。

完了条件: 採用データ源、取得できない航空会社・路線、価格表示条件、予約導線が検証表で説明できる。

### 2. 既存の検索を正しく動かす

1. 現在地を一度だけ取得し、その同じ座標を検索円と空港の絞り込みに渡す。位置情報が無効・拒否・取得失敗の場合は画面に理由と再試行を表示する。
2. 出発地と到着地の一致、過去の日付、人数の未選択を検索前に検証する。
3. 航空便検索を画面の `build` ごとに再実行しない。通信失敗、認証失敗、対象便なしを区別して表示し、再試行できるようにする。
4. 空港の写真取得に失敗しても、空港名と「出発地・目的地に設定」の操作は使えるようにする。

完了条件: 位置情報の許可・拒否の両方で操作が行き詰まらず、API エラーが「便なし」に化けない。入力検証と検索結果の各状態をテストで確認する。

### 3. 地域から探す画面を最小構成で作る

1. 旅行先を地図のピンまたは囲みで指定する。囲みは現在の描画機能を利用する。
2. 候補空港を「範囲内」と「周辺」の二群で提示する。最初は地理的距離で候補を絞り、地上交通の所要時間が得られたら順位付けに使う。
3. 各候補に空港名、目的地までの距離、出発地からの就航情報の有無を表示する。路線情報が未取得なら、その状態を明示する。
4. 候補から空港を選ぶと、現在の便検索画面へ出発地・到着地を引き継ぐ。

完了条件: 四国の任意の地点または囲みから、範囲外も含む候補空港を確認し、便検索へ進める。地図を動かすだけでは有料の運賃検索を実行しない。

### 4. データ源を交換できる構成にする

- Flutter 側に空港候補、路線、予定便、価格提示のモデルを分ける。価格には提供元、取得時刻、概算か実価格かを持たせる。
- 画面はデータ取得先を直接呼ばず、リポジトリを通す。欠損・失敗・未照会を別の状態として扱う。
- API キー、特に Amadeus のシークレットとトークン取得処理をアプリからサーバーへ移す。提供元ごとの認証情報、利用制限、キャッシュ方針はサーバーで管理する。
- 実価格は利用者が候補を選んだ時点で取得する。予約へ進む直前に価格と空席を再確認し、取得できなければその旨を表示する。

完了条件: データ源の切り替えで画面コードを変更せず、アプリ配布物にシークレットを含めない。

## その後の機能

1. 空港から目的地までの鉄道・バス・車の所要時間と費用を追加し、航空券を含めた総移動時間・総費用で比較する。
2. 週末、予算、直行便、現地到着時刻で候補を絞る。
3. 往復検索、最近の検索、保存した旅程を追加する。

## 実装時に守る表示ルール

- `便なし` は、その日付と空港の組み合わせを網羅的なデータ源で確認できた場合に限る。それ以外は `未確認` または `取得できませんでした` と表示する。
- 概算価格と実価格を混同しない。価格には取得時刻と提供元を添える。
- 予約リンクが特定の便に対応しない場合は、ボタンを `航空会社で検索` と表記する。
