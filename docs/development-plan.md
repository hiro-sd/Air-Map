# 地図から旅先を見つけるアプリの開発計画

## コンセプト

地図を眺めて、思いがけない行き先を見つけ、自分の地図に育てる。国内外の場所を対象に、発見、保存、再発見、小さな外出案へと体験をつなげる。空港・便検索は必要な旅で使う補助機能とする。

## 現在の試作

- 「見つける」では、国内外から手作業で選んだ22か所を収録した。画面内の場所を最大5件に絞り、有名な場所と少し意外な場所を混ぜる。地域・日英の紹介・テーマ・参照先・確認日は[同梱カタログ](../assets/data/travel_places.json)に記録する。
- 場所のピンと短い紹介を開き、「行きたい」「行った」「お気に入り」、非公開メモを端末内に保存できる。長押しで自分の場所を追加できる。
- 「おすすめ」では保存した場所のテーマと近さを使い、理由を添えて未保存の候補を最大3件示す。保存がないときは日替わりの候補を示し、意外な場所も混ぜる。
- 「マイマップ」で保存した場所を地図と一覧で見返し、分類で絞り込める。
- 以前の空港・便検索は別タブに残している。便・価格・空席の網羅性は未確認であり、この試作の中心機能には使わない。

## 次の実装順序

### 1. 発見体験を実機で確かめる

東京と四国で地図を動かし、場所の見つけやすさ、ピンとカードの重なり、地図の読みやすさ、保存までの操作数を確認する。数人に「眺めて楽しいか」「また開きたいか」を聞き、見たい場所と理由も記録する。場所がない地域では空白状態が長く続くため、試作の対象地域を明示し、次の地域を追加する判断材料にする。

### 2. 場所データを増やせる仕組みにする

場所ごとに座標、言語別の紹介、地域、テーマ、定番／意外の区分、参照先、確認日を持つJSONカタログを導入した。追加手順は[カタログ編集ガイド](curated-place-sources.md)に記録した。次は地域ごとに少数の場所を選んで追加し、紹介文と代表点を確認する。画像を使う場合は権利・出典・表示速度を確認する。大量の外部場所 API をそのまま地図に流さず、厳選した場所を維持する。

### 3. 「再発見する」を磨く

現在の端末内ルールで、保存した場所のテーマと近さから候補を変え、理由を表示できる。次は実際の利用状況を見て、推薦が同じ地域や同じテーマに偏らないか、紹介後に保存されるかを確認する。保存が少ない場合の候補や日替わりの頻度も調整する。推薦の理由と挙動が一致することを保つ。

### 4. 「旅にする」を追加する

選んだ2〜3か所を順番に並べ、小さな外出案として保存できるようにする。最初の経路確認は [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started) で地図アプリに引き継ぎ、所要時間や運賃を推測して表示しない。空港・便は長距離の旅で必要になった場合に結びつける。

### 5. 共有・他ユーザーの口コミを検討する

発見・保存・再訪の体験が成立してから、アカウント、同期、公開範囲、投稿管理を設計する。現時点のメモは端末内のみで、他ユーザーには表示しない。

## 技術上の注意

- Hive の記録は端末内にあり、アプリ削除や端末変更で引き継げない。同期・バックアップを導入する前にデータ移行方針を決める。
- 位置情報の許可がなくても地図の閲覧と保存は使えるようにする。
- 地図は Google Maps を使用する。場所の紹介文はアプリ内に同梱し、追加の有料 Places API には依存しない。
- 既存の Amadeus 便検索を網羅的な国内便・実運賃検索として扱わない。便データは旅行機能に必要になった時点で改めて検証する。

## 小さな完成条件

ユーザーが地図から予想外の場所を少なくとも一つ見つけ、理由がわかる紹介を読み、「行きたい」か「行った」に保存し、後日マイマップで再発見できる。まずはこの一連の体験が楽しいかを実機と利用者の反応で判断する。
